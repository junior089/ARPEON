# ARPEON 0.1.0 — Windows portable release candidate

Date: 2026-10-09. Platform: Windows x64.

Stage 9 simplifies Practice and Analysis preparation with initially folded advanced controls,
validation before starting and analysis-default recovery that preserves part and audio.
Settings survive navigation in the open window. They do not persist across app restarts.
See `docs/product/melhorias-etapa-9-2026-10-11.md` in `source.zip`.

Audio preparation now shares and locally saves input choice and A4 measurement reference
across Tuner, Practice and Analysis. Missing inputs have explicit recovery; microphone consent
is never restored. A two-second browser reference tone checks output volume and stops on
navigation. It does not retune system MIDI or calibrate hardware latency. See stage 8 in `source.zip`.

Updated build: 2026-10-11. The workstation now includes persisted appearance/layout settings,
A–B playback loops, coordinated microphone/reference playback, complete score pagination and
cursor timing corrections. The project library adds search, sorting, pagination, direct opening,
custom names and independent copies of saved scores. Copies retain import provenance; unsaved
changes and analysis history are not copied. See the stage reports in `docs/product` inside
`source.zip` for validation and remaining limits.

The latest build also adds analysis study guidance: coverage and capture cautions, musical
note names, suggested measures, stopped A–B preparation with adjustable playback tempo,
and navigation from a matched note to the score. Old reports remain readable. New analysis
continues to evaluate the whole part at its written tempo.

PDF/image recognition now offers phase progress, cancellation of the native job and comparison
with the original file. OMR draft preparation accepts incomplete measures and repeated identical
keys, preserving recognized events and disclosing provisional rhythm assumptions. It requires
review before opening or study. Five-page recognition was verified with the prepared Audiveris;
this does not guarantee accurate recognition for every score. See the stage 5 report in `source.zip`.

Rhythmic editing now offers named note values with one or two augmentation dots, plus an
advanced fraction mode that preserves unusual durations. Before applying, the inspector
explains collisions with following notes, measure boundaries and the available rest for
insertion. Undo/redo and autosave remain available. See the stage 6 report in `source.zip`.

Practice history now shows 20 attempts per page with exercise, result and inclusive local-date
filters. Musical names, dates and long-tone numbers use Portuguese formatting. Aggregate counts
cover the matching records, and retrying a read error does not block the exercise. The retained
5000 summaries contain no microphone samples. See the stage 7 report in `source.zip`.

Extract the entire ZIP, then open `ARPEON.exe` inside the `ARPEON` folder. The package
includes a Java 25 runtime and the offline web interface; Java and Node installations are
not needed to run it. Keep the console window open while using the browser interface.
Use **Encerrar ARPEON** in the interface, close the launcher window, or press Ctrl+C to stop the local server. `LEIA-ME.txt` has Portuguese
instructions. The adjacent `.sha256` file contains the ZIP checksum.

This candidate contains the implemented tuner, score editing/playback, beginner practice,
local import, OMR review, performance analysis and live score following. The milestone 9
machine-learning candidate was evaluated against the deterministic follower and is not
enabled in the application. Local import caps are documented in
`docs/product/import-capabilities.md` inside `source.zip`.

MusicXML playback supports chords, independent voices, bounded non-nested repeats and
pass-specific endings. Written notation stays in its original measure order; repeat expansion
is applied to playback. Nested repeats/endings and unsupported notation remain explicit errors.

The normal score, tuner and practice flows work offline. Wikimedia Commons import needs
network access. On first use, PDF/image recognition can download and prepare the official
Audiveris 5.11.0 package in the user's local data folder from **Importar**. This step needs
network access; later recognition works offline.
Imported scores and later edits are saved automatically to a local project after a short
debounce. **Salvar projeto** remains available for an immediate save. Projects are stored
locally under the user's ARPEON data directory. The application uses the system default
browser rather than a native webview.

Score event details are fetched when a measure is opened, and the study list displays up to
48 events per page. The initial score response therefore avoids sending every event at once;
the notation renderer still loads the complete MusicXML document.

The app is AGPL-3.0-or-later. Its corresponding source is in `source.zip`; application
and third-party notices are adjacent. The bundled Eclipse Temurin runtime retains its
module licenses in `runtime/legal`. The runtime version is 25.0.4.1+1; upstream source
and build details are available from https://adoptium.net/temurin/releases/?version=25.

Local Windows validation and remaining device-specific limitations are recorded in
`docs/releases/0.1.0-build-report.md` inside `source.zip`. The executable is unsigned; there is no system installer in this
candidate. Real microphone, MIDI synthesizer, Audiveris recognition and large-file
performance depend on the target hardware and input files.
