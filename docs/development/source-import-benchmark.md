# Milestone 5 import benchmark

Observed on Windows with JDK 25 on 2026-10-08 using `SourceImportBenchmarkTest`.
These are diagnostic measurements, not pass/fail thresholds or a throughput promise.

| Stage | Fixture | Iterations | Elapsed | Thread-allocated memory |
| --- | --- | ---: | ---: | ---: |
| Provider filtering | One approved Commons `File:` URL | 5,000 | 1.865 ms | 160,000 bytes |
| Fetch boundary | In-memory responses, 22-byte metadata and 35-byte MIDI | 1,000 pairs | 4.745 ms | 864,000 bytes |
| Local MIDI parsing | One monophonic 35-byte MIDI | 200 | 73.480 ms | 1,673,720 bytes |

The fetch stage copies fixture bytes in memory and makes **no network request**. It measures
adapter overhead, not Commons response time, DNS, TLS or transfer. A user-requested import
also makes two sequential HTTPS requests with an eight-second per-request timeout, enforces
response-size bounds and obeys provider throttling. Live network latency, actual 1 MiB MIDI
parsing and many-source sessions remain unmeasured. Re-run the diagnostic after relevant code
or runtime changes; do not extrapolate from this tiny fixture to bulk import performance.

## MusicXML StAX boundary

Observed on 2026-10-09 on Microsoft Windows 10.0.26220 with Microsoft OpenJDK
25.0.4.1, using the Gradle test worker configured with `-Xmx512m`. CPU model was
not available to the sandbox, so this record is incomplete for machine-to-machine
comparison. The test performs one warm-up import and three measured imports.

| Stage | Generated fixture | Runs | Mean elapsed | Mean thread-allocated memory |
| --- | --- | ---: | ---: | ---: |
| MusicXML streaming import | 2,048 measures, 16,384 notes, 1,721,557 bytes | 3 | 73.73 ms | 54,260,459 bytes |

The fixture is generated by `SourceImportBenchmarkTest`; it is not a licensed
real-world score and does not include HTTP serialization, browser memory, SVG
rendering, MXL decompression, or OMR. Allocation is per-thread cumulative
allocation during an import, not peak live heap. Treat this as a reproducible
server-side stress diagnostic at the current structural limits, not a performance
guarantee. Re-run on representative licensed scores and record peak heap and
browser measurements before changing the published limits.
